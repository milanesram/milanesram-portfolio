## 6. Design direction

### Visual posture

Modern, restrained, and institutionally credible. The site should feel closer to a CISO brief or a professional-services partner page than to a developer dribbble shot or a personal blog.

Recommended attributes:

- Light default theme with a dark professional option only if it stays highly readable
- Narrow accent color (deep navy, ink, or muted teal) — not neon cyber-green
- Strong typographic hierarchy; generous whitespace; short paragraphs
- Scannable proof chips (credentials, work authorization, role family)
- Desktop-first for recruiter ATS/email browsing; fully usable on mobile
- Motion used sparingly (section reveal, no hero animation theater)

### UX principles

- **Scan first, diligence second.** Homepage is a briefing. Inner pages hold evidence.
- **Two doors, one house.** Track CTAs are visible without splitting the brand.
- **Evidence over adjectives.** Prefer a launched system, a credential, or an approved metric to a slogan.
- **Update without a redesign.** All narrative blocks should map to CMS fields (see `INITIAL_DATA_MODEL.md`).
- **Privacy by example.** No public phone number by default; professional email + LinkedIn + secure contact form; no private CV download.

### Content design patterns

- Experience entries: organization, public title, dates, 3–5 bullets maximum on the public page
- Metrics: only clearly source-supported figures, each with exact context (period, baseline, unit); never a compressed or combined figure
- Case study: problem → approach → controls → limits → what a reviewer can inspect
- Credentials: issuer, name, status; Philippine law license visually separated from U.S.-market certs
- Writing: title, publisher, year, outbound link; short abstract, not the full paper

### Brand assets still required

See `PHASE_1_REVIEW.md` (missing assets). Design should not proceed to implementation around a missing headshot, mark, or PrivAI Guard visuals; placeholders are acceptable only in a later Phase 2 prototype.
